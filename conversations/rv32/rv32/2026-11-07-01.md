## 1895 · 助手

2026-11-07 08:16:47.819 UTC

之前做的是 **I-cache 替换策略探索**，分为“模型筛选”和“真实 RTL 比较”两步。这里要特别区分：**模型 miss 比、绝对 miss rate、RTL 执行时间，是三个不同指标。**

### 当时怎么评估

先采集软件执行的退休 PC 轨迹，用 **C++ Cache 模型**依次模拟访问：

- 根据容量、路数、行大小计算 set 和 tag。
- 模拟命中、缺失、受害行选择及替换状态更新。
- 同一轨迹、同一缓存结构下比较策略；另行扫描容量、路数和行大小。
- 在线算法只使用过去信息；OPT 使用未来访问，仅作为离线上界。

总共扫描了 **910 个结构与策略组合**。模型筛选后，进行了 **30 个整核 RTL/PPA 配置比较**，检查真实周期数、错误路径访问、总线竞争、面积与 STA，通过这些结果最终选型。

模型用的是退休轨迹，**不包含错误路径取指和真实握手时序，因此模型 miss rate 不能直接换算为 IPC。**

### 最终选型结构下，各策略表现

固定 **1 KiB、4 路、32 B 行**，在六项开发轨迹上，保存的汇总指标是：

**各负载 miss 次数相对 Tree-PLRU 的比值，再取几何平均。它不是绝对 miss rate。**

| 替换策略 | 相对 miss 比，PLRU=1 |
|---|---:|
| FIFO | 1.1728 |
| LRU | 1.0644 |
| Tree-PLRU | 1.0000 |
| Random | 1.0221 |
| LIP | 1.0001 |
| BIP | 0.9807 |
| SRRIP | 0.9993 |
| 固定插入 RRPV=3 | 0.9845 |
| BRRIP | 0.9651 |
| DRRIP | 0.9778 |
| **分段访问 RRIP，最终采用的算法** | **0.9043** |
| 分段访问＋PC 反馈 | 1.5585 |
| 分段访问＋路径反馈 | 0.9842 |
| OPT，离线上界 | 0.6590 |

也就是说，最终算法在这组模型输入上，**相对 PLRU 的 miss 几何平均减少约 9.57%**。PC 反馈方案明显退化；路径反馈改善了它，但仍不如单纯的分段访问 RRIP。

“分段访问”指：连续访问同一条 cache line 时，不反复提高其保留优先级；离开这条 line 后再次命中，才提升优先级。

### 有绝对 miss rate 的记录吗？

有。较早的容量扫描使用 **MicroBench test 完整功能轨迹，共 872,053 条指令**。统一采用 **2 路、16 B 行、冷启动**，根据记录中的 miss 次数计算：

| I-cache 容量 | FIFO | LRU | SRRIP | OPT |
|---|---:|---:|---:|---:|
| 256 B | 2.8485% | 2.3902% | 2.8065% | 1.9600% |
| 512 B | 0.9654% | 0.8438% | 0.9653% | 0.7057% |
| 1 KiB | 0.3766% | 0.3634% | 0.3739% | 0.3034% |
| 2 KiB | 0.2781% | 0.2656% | 0.2797% | 0.2174% |

这里的分母是整条功能轨迹的指令访问数，包含启动、初始化、打印与校验，**不是 train，也不是原生 Total/Scored 计时窗口**。而且它的结构是两路、16 B 行，不能与上面的四路、32 B 行表直接比较。

最终结论是：**容量和组织调整贡献了主要收益，替换算法贡献了较小的额外收益。**进入 RTL 后，最终分段策略相对同结构简单 SRRIP，在保留集上的平均用时只减少约 **0.52%**，面积时间积减少约 **1.13%**；不能把模型中约 9.6% 的 miss 改善说成约 9.6% 的加速。

记录见：[完整选型报告](/home/yong/ysyx/ysyx-workbench-rv32-interview/npc/docs/verification/ICACHE_SELECTION_2026-09-21.md)和[容量模型报告](/home/yong/ysyx/ysyx-workbench-rv32-interview/npc/docs/verification/ICACHE_CAPACITY_EXPLORATION_2026-09-21.md)。本次核对的是已保存报告，没有重新运行模型；最终六项开发负载的逐策略**绝对 miss rate**，当前报告只给了上述归一化汇总，不能把它冒充绝对值。

**应该同时报告绝对 miss rate。之前只给相对值，信息不完整。**而且表头准确说是“相对 miss 次数”，不是绝对 miss rate。

两者分别回答：

- **绝对 miss rate＝miss 次数 ÷ Cache 查询次数**：实际有多少比例的访问缺失。
- **相对 miss 比＝某策略 miss 次数 ÷ 参照策略 miss 次数**：换策略改善了多少。

跨负载汇总用相对值，是为了让不同访问规模的负载都有权重；但相对值会隐藏缺失率本身。例如从 0.1% 降到 0.09%，和从 10% 降到 9%，都是减少 10%，对执行时间的影响却可能很不一样。

我刚核对了保存的数据。**最终采用的 1 KiB／4 路／32 B 行／分段 RRIP，在整核 RTL 实验中的绝对 miss rate 如下**：

|---|---:|---:|---:|---:|
| JSON/BPE | 1.7430% | 2.0257% | 1.3696% | 1.5148% |
| 量化数据装载 | 0.3205% | 0.3290% | 0.1935% | 0.1899% |
| Runtime 图执行 | 3.6328% | 3.4899% | 2.4499% | 2.3249% |

## 1905 · 助手

2026-11-07 08:36:08.171 UTC

**不是越小差别就越明显。替换策略通常在“容量不够覆盖工作集、但仍有机会保留重用数据”的区间更有作用。**

我刚用恢复的数据比较了不同容量，固定 **4 路、32 B 行、同样六项负载**，绝对 miss rate 如下：

| I-cache 容量 | FIFO | PLRU | SRRIP | 分段 RRIP |
|---|---:|---:|---:|---:|
| 256 B | 4.4114% | 4.4570% | 4.4439% | 4.4928% |
| 512 B | 3.7975% | 3.7692% | 3.6885% | **3.3239%** |
| 1 KiB | 1.9542% | 1.7194% | 1.8240% | **1.5089%** |
| 2 KiB | 0.6511% | 0.4715% | 0.4935% | **0.4175%** |
| 4 KiB | 0.1510% | **0.1345%** | 0.1497% | 0.1438% |
| 8 KiB | 0.0972% | 0.0972% | 0.0972% | 0.0972% |

这组结果体现了三种情况：

- **容量很小，如 256 B**：很多指令行难以保留到下次使用，各策略都频繁替换，分段 RRIP 甚至略差于 PLRU。
- **容量适中，如 512 B～2 KiB**：选择保留哪条行开始产生明显影响，分段 RRIP 比 PLRU 少约 **11%～12% 的 miss**。
- **容量足够大，如 8 KiB**：这些负载已经接近只剩首次访问缺失，换策略基本没有收益。

还要区分**相对改善和绝对改善**：1 KiB 时，分段 RRIP 比 PLRU 少 **0.2105 个百分点**；2 KiB 时只少 **0.0540 个百分点**。虽然相对降幅接近，能减少的 miss 数不同，对性能的价值也不同。

所以我们应该找的是：**在目标负载下，增加容量和改进策略，哪个带来的收益更值得其面积与时序成本。**这组数据支持分段 RRIP 在 512 B～2 KiB 范围内有价值，并不支持它在所有容量下都更好。

## 1908 · 助手

2026-11-07 08:37:36.981 UTC

**是的，之前报告的面积，是完成 RTL 综合和标准单元映射后得到的，不是 Cache 软件模型估算的。**

流程是：

**RTL → Yosys 综合与逻辑优化 → 映射到 NanGate45 标准单元库 → 统计各单元面积之和 → 对映射网表做 STA。**

需要明确三个范围：

- **统计的是整个 CPU 核及复位包装**，包含流水线、预测器、I-cache、D-cache 等，不是单独 Cache 的面积；不包含完整 SoC、外设及外部存储。
- **Cache 阵列也计入面积**，当时使用标准单元实现，没有采用 SRAM 宏，因此容量增加会带来较明显的面积增长。
- **这是综合后的单元面积，不是布局布线后的核心占地面积**。没有计入布局留白、完整时钟树和布线后新增单元等成本。

例如，之前 Cache 选型时的 **约 101,433 μm²**，就是该配置完成综合映射后的全核面积。最近并行取指版本保留的综合报告则为 **99,535.072 μm²**，对应另一版 RTL，不能混为同一次测量。[原始面积报告](/home/yong/ysyx/ysyx-workbench-rv32-interview/npc/docs/verification/data/parallel-fetch-20261025/final/synth_stat.txt:82)

另外，**910 项 Cache 模型扫描没有全部做综合**；筛选后进入整核 RTL/PPA 比较的是 30 项配置。
