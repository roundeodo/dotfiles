这是正常的：**Total 多出来的那些代码，IPC 更高，因此把整体平均值拉高了。**

源码中的统计范围是：

- **Scored**：10 个子测试各自 `run()` 的计时窗口之和。
- **Total**：整个测试循环，还包括数据准备、结果验证、循环内打印和计分。

根据这次[报告](/home/yong/ysyx/ysyx-workbench-rv32-interview/npc/result/performance/passive-train-20260922T071755Z/report.json)，相减可以得到：

| 范围 | 退休指令数（百万条） | 周期数（百万拍） | IPC |
|---|---:|---:|---:|
| Scored | 186.810 | 522.916 | 0.357247 |
| Total 中 Scored 之外的部分 | 80.018 | 124.936 | **0.640473** |
| Total | 266.828 | 647.852 | **0.411866** |

所以差异可以完全由计数解释。**IPC 是退休指令数÷周期数，时间更短并不意味着 IPC 更高**；整体 IPC 也不能直接取各段 IPC 的算术平均。

| 项目 | 配置 |
|---|---|
| 数据容量 | **256 B** |
| 相联度 | **2 路，8 组** |
| Cache line | **16 B，即 4 个 RV32 数据字** |
| 总行数 | 16 行 |
| 写策略 | Write-back / Write-allocate |
| 替换策略 | 无效路优先，否则组内轮转 |
| 访存结构 | 阻塞式，miss 处理期间阻塞后续普通查询 |

本轮 I-cache 探索沿用了这套 D-cache。此次**全程序**统计中，其命中率为 **80.744%**，平均命中响应 **1 周期**、平均 miss 响应 **105.62 周期**。

## 0769 · 助手

2026-09-22 11:26:51.397 UTC

**I-cache 这轮做了实质性的探索；分支预测做过早期模型比较和本轮瓶颈统计，但你要求的“结合近期研究，完成新机制的实现与比较”，还没有完成。** 这两部分需要明确区分。

**I-cache 具体探索了什么**

| 方向 | 实际完成的内容 |
|---|---|
| 容量和组织 | 模型扫描 256 B～16 KiB、1/2/4/8 路、16/32/64 B 缓存行 |
| 经典替换策略 | 比较 FIFO、LRU、Tree-PLRU、随机、LIP/BIP、SRRIP、BRRIP、DRRIP 等 |
| 研究启发的候选 | 实现退休有用性反馈、分段访问 RRIP，以及加入 PC、路径信息的复用预测原型 |
| 电路实现 | 优化替换查询的组合路径，加入必要的状态前递，检查面积和时序代价 |

整体完成了 **910 个模型组合、30 个整核 RTL/PPA 配置比较**。910 项不是全部做了 RTL；C++ 模型先筛选缺失率和流量，再通过真实 RTL 测量周期、面积和合法频率。具体记录见[选型报告](/home/yong/ysyx/ysyx-workbench-rv32-interview/npc/docs/verification/ICACHE_SELECTION_2026-09-21.md)。

**是否参考了近期前沿研究？有，但实现程度各不相同。**

| 研究 | 原论文关注什么 | 本项目做到哪里 |
|---|---|---|
| [Bumper，ISCA 2026](https://www.pure.ed.ac.uk/ws/portalfiles/portal/654859698/VavouliotisEtalISCA2026Bumper.pdf) | 用退休信息识别有用指令行，改善统一 L2 的管理 | 将核心思想改造为小型 L1I 的退休反馈原型；未胜过简单对照，没有选入当前配置 |
| [ICARUS，ASPLOS 2026](https://webs.um.es/aros/papers/pdfs/vkalbande-asplos26.pdf) | 结合分支历史、关键性和复用信息管理 L2 指令行 | 做了适用性分析；没有实现完整 ICARUS |
| [ACIC，2022 年公开稿](https://arxiv.org/abs/2211.10480) | 区分连续空间访问与后续复用，通过过滤器和预测器控制准入 | 借鉴访问特征，形成分段访问 RRIP；没有完整实现其过滤器与准入结构 |
| [GHRP，ISCA 2018](https://www.elbagarza.com/pdfs/ghrp_isca2018.pdf) | 利用历史信息预测 I-cache/BTB 条目复用 | 参考其思路实现简化学习原型；属于经典研究，不能称为近期成果 |

因此，准确的表述是：**参考了近期论文，针对本核实现并验证了简化候选。当前方案仍属于 RRIP 家族的改进，不能称为完整复现了上述前沿方案。**

目前选中的配置是 **1 KiB、4 路、32 B 行，分段访问 RRIP，加替换查询旁路**。其策略很具体：

- 连续读取同一缓存行，不反复提高它的保留优先级。
- 离开该行后再次命中，才提高优先级。
- 查询路径避开不需要经过的分配、老化逻辑，减少组合延迟。

收益也要分清：在 AI 代理负载的保留测试集上，相比同容量、同路数、同行大小的简单 SRRIP，按各自通过 STA 的频率比较，**平均用时仅减少 0.52%，面积×时间减少 1.13%**。相对原来 256 B 基线的大幅提升，主要来自缓存容量和组织调整。MicroBench test 上，该配置甚至比简单 SRRIP 更慢；它是既定均衡目标下的选择，并非所有程序都最快。

**分支预测到底做过什么**

不能说完全没做，但完成程度明显不如 I-cache：

1. **早期做过经典策略的模型探索。** 仓库中的 [Branchsim](/home/yong/ysyx/ysyx-workbench-rv32-interview/npc/tools/branchsim/branchsim.cpp) 比较过 bimodal、gshare，以及 BTB、RAS 的配置。这是退休轨迹模型，不能替代整核时序仿真。
2. **本轮增加了实际错误分类统计。** 区分 BTB 未命中、方向错误、目标错误，并观察返回预测等问题；近期 BTB 预填充方向也做过初步文献筛选。
3. **本轮没有实现新的分支预测算法。** 当前仍是 16 项、两位饱和计数器 BHT，16 项两路 BTB，以及 4 项 RAS；这轮 I-cache 探索没有修改这些模块。

尤其要避免混淆：**I-cache 原型中使用“路径历史预测复用”，不等于已经实现了新的分支方向预测器。**

你要求的分支预测前沿探索，尚缺少“近期论文与 artifact 核验 → 当前负载模型筛选 → 同预算简单对照 → 新机制 RTL → 正确性与 PPA 比较”这一整轮工作。之前的预测器拆分、去掉冗余寄存级和经典 Branchsim 比较，都不能代替这部分交付。

## 0772 · 助手

2026-09-22 11:43:18.614 UTC

**有。当前选中的策略，最直接借鉴的是 ACIC 对“行内连续访问”和“后续再次复用”的区分，基础算法则来自 SRRIP。** 查询旁路属于针对本核接口做的电路优化。这三部分可以分别说明。

**第一，沿用 SRRIP 的低成本替换框架。**

每个缓存行保存两位 RRPV，取值 0～3：值越大，越优先被替换。当前实现中新行插入为 2，确认复用后降到 0，需要替换时对组内状态进行老化。这部分来自经典的 [RRIP 研究](https://jaleels.org/ajaleel/publications/isca2010-rrip.pdf)，不是近期提出的新算法。

**第二，借鉴 ACIC，改变“什么访问值得提高保留优先级”。这是当前策略最主要的研究借鉴。**

ACIC 指出，指令缓存中的密集访问可能只是空间局部性和短时间访问集中，不能直接说明这行之后还会再次使用。原论文通过过滤器和复用预测器处理这个问题。[ACIC 原文](https://arxiv.org/abs/2211.10480)

对应到我们当前的 **32 B 缓存行、RV32I 指令**：

- 一行容纳 8 条指令。第一条取指触发回填，后面连续读取同一行时会产生多个命中。
- 普通 SRRIP 在后续命中时，就把该行的 RRPV 从 2 提升到保留优先级最高的 0。
- 当前策略让这些连续命中保持原有优先级；**访问过其他缓存行，再回来命中这一行，才把 RRPV 设为 0。**

这样，单次顺序执行经过的代码不会仅因为行内命中，就立即获得最高保留优先级。

我们没有实现完整 ACIC 的过滤器和准入预测器，而是用“前一次访问的行地址＋有效位”判断是否开始新的访问段。当前配置额外需要 **28 位状态及地址比较逻辑**，不增加流水级。这是针对小核的简化，也有局限：完全在同一行内反复执行的循环，同样会被视为连续访问段。

**第三，查询旁路来自本核的电路分析。**

当前阻塞式 I-cache 中，miss 分配与新查询不能同时发生。因此，替换查询无需经过 miss 分配时的整组老化、插入选择逻辑，只需要处理可能同时发生的命中更新前递。

这项修改不改变策略的访问周期数，也不增加流水级；已测对照中，通过 STA 的频点从 **600 MHz 提高到 720 MHz**。它属于电路实现收益，不能归为 ACIC 的算法收益。具体结构见[设计记录](/home/yong/ysyx/ysyx-workbench-rv32-interview/npc/docs/microarchitecture/ICACHE_REPLACEMENT_DESIGN.md)。

所以，当前方案准确的描述是：**在 SRRIP 框架中，引入受 ACIC 启发的跨访问段命中提升规则，再针对本核优化替换查询路径。** Bumper 的退休反馈和 GHRP 启发的学习表做过其他候选实验，但没有进入当前选中策略。
